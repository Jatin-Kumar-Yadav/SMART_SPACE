# Wokwi integration notes

Research done with WebSearch/WebFetch on 2026-11-01. The build sandbox cannot reach wokwi.com, so **nothing
generated by SmartSpace 3D has been loaded into Wokwi by us**. Part names/pins below are taken from the
sources cited; items marked *unverified* were not confirmed by any source we could reach.

## diagram.json (confirmed)
Top level: `version` (1), `author`, `editor` ("wokwi"), `parts`, `connections`, optional `serialMonitor`.
Part: `id`, `type`, `left`, `top`, `attrs`, `rotate`, `hide`. Connection: `[ "part:pin", "part:pin", "color", [routing hints] ]`.
Routing hints are `v<px>` / `h<px>` strings; Wokwi draws only horizontal/vertical wire segments.

## NOT available in Wokwi (per the supported-hardware page)
| Real component | Wokwi status | What the Wokwi copy does (clearly labelled, never silent) |
|---|---|---|
| BME280 | not listed (only BMP180) | replaced by DHT22 in the Wokwi copy only |
| BH1750 | not listed | replaced by the photoresistor module (analog `AO`) in the Wokwi copy only |
| DC motor | not listed (servo/stepper only) | replaced by an LED + 220 Ω resistor on the same PWM pin ("motor substitute") |
| N-MOSFET / flyback diode | not listed | omitted from the Wokwi copy (the substitute LED needs no driver); the real design keeps them |
| TCA9548A, PCA9685, ADS1115 | not listed | not exported — the Wokwi export is refused when the plan needs them, with an explanation |
| Raspberry Pi 3/4/5 | only Pico family is supported | Wokwi export unavailable for the Raspberry Pi controller |

Because the substitutions change the firmware (different sensor libraries), the Wokwi export regenerates the
sketch for the substituted configuration. The real-hardware firmware/wiring are generated separately and are unchanged.

## libraries.txt (confirmed)
Plain text, one Arduino Library Manager name per line, `#` comments, optional `@version`.

## wokwi.toml (confirmed keys)
`[wokwi] version = 1`, `firmware = '<relative path>'`, optional `elf`, `rfc2217ServerPort`; `[[net.forward]] from/to`.
`wokwi.toml` is only used by the VS Code/CLI workflow (it points at a *compiled* firmware). The web editor compiles
`sketch.ino` itself, so for the web workflow `wokwi.toml` is not needed; we still ship one for the VS Code workflow
with a placeholder firmware path that must be adjusted to your build output.

## Wi-Fi / MQTT in the simulator (confirmed)
Virtual access point `Wokwi-GUEST` (open, channel 6): `WiFi.begin("Wokwi-GUEST", "", 6);`. TCP/UDP work (no ICMP).
The web simulator reaches the internet, **not** your computer's localhost; reaching a local broker needs the
paid *Private Wokwi IoT Gateway* (not Safari). Our Wokwi sketch therefore defaults to a public test broker placeholder
that you must set; sensor values in Wokwi are set with the part's attributes, not by the live gateway.

## Importing a project (finding)
We found **no documented URL or API that imports a diagram.json/sketch.ino from a link or file**. The page
https://wokwi.com/projects/new/esp32 opens a blank ESP32 project with the editor tabs. Our "Open in Wokwi" button
therefore opens that page (ESP32) and shows the exact paste steps with Copy buttons per file.
For Arduino Uno the analogous URL `https://wokwi.com/projects/new/arduino-uno` is *unverified* (it could not be fetched);
the UI says so and also describes "New project → Arduino Uno" as the fallback.

## Not verified
- None of the generated diagram.json files has been loaded in Wokwi or linted with `wokwi-cli lint`.
- `3V3`/`5V` pin spelling on `board-esp32-devkit-c-v4` (see above).
- Simulated sensor values; DHT22/DS18B20 libraries on Wokwi's ESP32 build.
